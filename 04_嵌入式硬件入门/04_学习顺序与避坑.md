# 嵌入式学习顺序与避坑指南

## 1. 学习顺序（为什么不能乱）

```
电源与地  →  GPIO  →  定时器  →  串口  →  中断/DMA  →
ADC  →  I2C/SPI  →  电机与编码器  →  PID  →
RTOS  →  CAN  →  Linux/ROS 2  →  FOC/力控  →  系统集成
```

### 为什么是这个顺序

1. **先电源与地**：90% 的"玄学 bug"是供电和共地问题。不理解这个，后面所有调试都是猜。
2. **GPIO → 定时器**：定时器是嵌入式的核心（PWM、捕获、编码器、定时中断全靠它）。
3. **串口 → 中断/DMA**：串口是唯一的调试窗口；中断和 DMA 决定你的代码是否"实时"。
4. **ADC → I2C/SPI**：模拟量与数字传感器，是所有感知的入口。
5. **电机与编码器 → PID**：第一个真正的闭环系统，也是机器人控制的最小单元。
6. **RTOS**：当你有 3 个以上任务时，裸机 `while(1)` 就不够用了。
7. **CAN**：多电机、多板子系统的标准总线。
8. **Linux/ROS 2**：从"单板控制"升级到"系统集成"。
9. **FOC/力控**：从"能动"升级到"动得柔顺"。
10. **系统集成**：把上面全部串起来，做成一个机器人。

**跳步的代价**：
- 跳过定时器直接学 PID → 采样周期不稳，永远调不好
- 跳过裸机直接学 RTOS → 不知道 RTOS 解决了什么问题
- 跳过 MCU 直接学 ROS 2 → 只会调包，做不了本体

## 2. 每个阶段的最小验证

| 阶段 | 最小验证 | 判定标准 |
|---|---|---|
| GPIO | 按键控制 LED | 无抖动、无漏按 |
| 定时器 | PWM 呼吸灯 | 亮度线性变化 |
| 串口 | 自定义协议收发 | 1 小时不丢包 |
| 中断/DMA | 不定长串口帧 | 高波特率不丢数据 |
| ADC | 电位器采样 | 波形平滑无跳变 |
| I2C | 读 MPU6050 | 数据稳定、无 NACK |
| SPI | 读 ICM42688 | 1 kHz 采样不丢 |
| 编码器 | 手动转电机计数 | 正反转计数正确 |
| PID | 电机定速 | 阶跃响应无持续震荡 |
| RTOS | 三任务并行 | 无栈溢出、无优先级反转 |
| CAN | 双板通信 | 1 小时无错误帧 |
| ROS 2 | IMU 上 RViz | 姿态实时、无延迟 |
| FOC | 力矩模式 | 电流跟随指令 |

## 3. 硬件避坑（按发生频率排序）

### 3.1 电源问题（最高频）
| 现象 | 原因 | 解决 |
|---|---|---|
| MCU 莫名复位 | 电机启动拉低电压 | 电机/逻辑分开供电，加大电容 |
| 传感器数据乱跳 | 电源纹波大 | 加 LC 滤波、独立 LDO |
| 舵机抖动 | 电流不足 | 用 5V 5A+ 电源，不要从 MCU 取电 |
| 板子发烫 | 短路或反接 | 上电前用万用表测通断 |

### 3.2 接地问题
- 所有模块必须**共地**，否则信号参考电平不同，通信必挂。
- 大电流地与信号地**单点连接**，避免地环路。
- 长距离通信（如 CAN、RS485）用双绞线 + 终端电阻。

### 3.3 电平问题
- 3.3V MCU 接 5V 传感器：用分压或电平转换芯片（TXS0108E）。
- 5V  tolerated 的引脚（很多 STM32 引脚是 FT）可以直接接，但要查数据手册。
- I2C 上拉电阻：3.3V 系统用 4.7kΩ，5V 系统用 10kΩ 并注意电平。

### 3.4 通信问题
| 总线 | 常见坑 |
|---|---|
| UART | 波特率不匹配、TX/RX 接反、没共地 |
| I2C | 地址冲突、上拉缺失、总线锁死（需 9 个时钟脉冲恢复） |
| SPI | CPOL/CPHA 配错、片选时序、MISO 悬空 |
| CAN | 缺 120Ω 终端电阻、波特率不匹配、ID 冲突 |

### 3.5 机械与结构
- 舵机不要长时间堵转，会烧电机或扫齿。
- 3D 打印件受力方向要考虑层间强度（Z 轴最弱）。
- 机械臂重心尽量靠近底座，减少舵机负载。
- 所有紧固件加螺纹胶，振动会松。

## 4. 软件避坑

### 4.1 实时性
- **不要在中断里做耗时操作**（如 `printf`、浮点运算、动态内存分配）。
- **不要用 `HAL_Delay` 做控制**，它会阻塞整个系统。
- 控制循环用定时器中断或 RTOS 高优先级任务，周期固定。
- 关中断时间要短，否则会丢外部事件。

### 4.2 内存
- 嵌入式不要用 `malloc/free`（碎片化），用静态分配。
- 栈大小要留余量，RTOS 任务栈溢出是最隐蔽的 bug。
- 大数组放全局或静态区，不要放栈上。

### 4.3 调试
- 逻辑分析仪 > 示波器 > 串口打印，按问题类型选工具。
- 串口打印要用 DMA 或环形缓冲，否则影响实时性。
- 用 GPIO 翻转 + 示波器测函数执行时间，比 `printf` 计时准。

### 4.4 版本管理
- 固件也要 Git，每次"能跑"的版本打 tag。
- 记录每次改动的硬件配置（哪根线接哪个引脚），否则一周后就忘了。

---

## 5. 学习心态

1. **接受"大部分时间在调试"**：写代码 20%，调试 80%，这是嵌入式常态。
2. **一次只改一个变量**：同时改硬件和软件，出问题无法定位。
3. **先让它"能跑"，再让它"跑好"**：不要一开始就追求完美架构。
4. **记录失败**：每个 bug 的排查过程写成笔记，三个月后你会感谢自己。
5. **不要怕烧板子**：买两块，烧一块还有一块；怕烧就永远学不会。

## 6. 12 周入门计划（可直接照做）

| 周 | 内容 | 产出 |
|---|---|---|
| 1 | 环境搭建、blink、串口打印 | 能烧录、能打印 |
| 2 | GPIO 按键、外部中断 | 按键控制 LED |
| 3 | 定时器 PWM | 呼吸灯 + 舵机转动 |
| 4 | 串口 DMA + 协议 | 上位机收发数据 |
| 5 | ADC + DMA | 电位器曲线 |
| 6 | I2C 读 MPU6050 | 串口输出加速度/角速度 |
| 7 | 互补滤波姿态解算 | 上位机 3D 姿态 |
| 8 | 编码器 + 定时器捕获 | 转速测量 |
| 9 | 电机驱动 + PID 调速 | 定速闭环 |
| 10 | PID 位置控制 | 定点转动 |
| 11 | FreeRTOS 重构 | 多任务系统 |
| 12 | 综合项目（小车/云台/机械臂） | 演示视频 |

每周投入 10 小时，3 个月可以完成从"零"到"能独立做闭环项目"。
